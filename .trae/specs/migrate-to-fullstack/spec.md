# 农村一标四实系统前后端分离改造 Spec

## Why
目前“农村一标四实系统”仅为一个纯前端应用，业务数据（地址、人口、房屋、工单等）全部依靠前端 `Zustand` 状态库在内存中模拟，刷新页面后数据即丢失，无法进行真正的数据持久化和多端协同作业。为了使系统真正投入生产环境使用，必须引入真实的后端服务和数据库，将架构升级为完整的前后端分离系统。

## What Changes
- **新建后端服务**：在根目录下创建 `api` 目录，采用 `Node.js + Express + TypeScript` 技术栈搭建后端 API 服务。
- **引入数据库与 ORM**：使用 `Prisma ORM` 连接数据库（本地沙盒环境默认推荐 `SQLite`，便于快速跑通；生产可无缝切换 `PostgreSQL`），实现数据持久化。
- **构建真实数据模型**：建立 `Address`（标准地址）、`Population`（实有人口）、`Order`（隐患工单）等核心数据表。
- **开发 RESTful 接口**：为前端的 PC 管理后台、移动端、大屏提供数据查询、上报、更新和销账的 API 接口。
- **改造前端数据流**：移除前端 `src/store/index.ts` 中的硬编码 Mock 数据，改为通过 HTTP 请求（如 `fetch` 或 `axios`）调用后端 API 接口，并更新 `Zustand` 状态。
- **BREAKING**: 前端应用将不再自带模拟数据，必须启动后端服务才能正常使用系统功能。

## Impact
- Affected specs: 系统的整体数据流向、启动方式、部署架构。
- Affected code: 
  - 新增 `api/*` 目录及后端全量代码。
  - 修改前端 `src/store/index.ts` 数据获取逻辑。
  - 修改前端业务组件中触发数据变更（如提交工单、派单、销账）的逻辑。

## ADDED Requirements
### Requirement: 数据持久化与接口服务
系统 SHALL 提供稳定的 RESTful API 服务，实现对“一标四实”数据的持久化存取。

#### Scenario: 移动端上报隐患落库
- **WHEN** 村干部在移动端提交随手拍隐患工单。
- **THEN** 前端发送 POST 请求至后端，后端将工单信息写入数据库，并返回创建成功的响应，数据永久保存。

#### Scenario: PC端与大屏端数据协同
- **WHEN** PC端内勤对隐患工单执行“核销”操作。
- **THEN** 后端更新数据库中该工单状态为“已销账”，大屏端在下次拉取数据时，红色的隐患预警点阵将自动消失。

## MODIFIED Requirements
### Requirement: 状态管理机制升级
原来的 `Zustand` 直接同步修改本地数组的逻辑，将变更为“异步调用 API -> 获取最新数据 -> 更新本地 Store”的真实业务流转模式。
